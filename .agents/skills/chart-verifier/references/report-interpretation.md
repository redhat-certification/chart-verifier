# Interpreting verify output and report summaries

## Verify output

`<chart-verifier-bin> verify <chart-uri>` prints the result of each check and an overall result, and can emit JSON or YAML (`--output json|yaml`) and write a report file (`--write-to-file`, producing `chartverifier/report.yaml`).

Per-check outcomes and what to do next:

- **PASS** - the check found the chart to be in compliance.
- **FAIL** - the check found a problem. The output names the check and, in the error log, a remedial action. Address the problem and re-run the verifier. If troubleshooting, you can shorten the feedback loop with the check by specifying the check name via the `--enable` flag.
- **SKIPPED** - the check did not run as it was not applicable. Tell the user which checks were skipped and why; if the skip was caused by missing prerequisites (cluster, credentials, network), offer to re-run with the prerequisite in place - after asking.

## Runtime errors
In some cases, the command execution itself can fail (e.g.bad chart URI, unreachable remote, malformed chart archive). The error text, STDERR, and the error log (`chartverifier/verifier-<timestamp>.log`) can identify the cause. Suggest a concrete fix: correct the URI, download the chart locally, install prerequisites, or use an appropriate `--kube-context`. If insufficient guidance exists in logs, you can re-run with the `--debug` flag.

## Report summaries

`<chart-verifier-bin> report all <report-file>` summarizes an existing report.

Set the profile vendor/version with `--set` (partner is the default, so it does not require this flag) to evaluate the report output against the appropriate policy.

Digest validation is on by default: the CLI checks that the digest recorded in the report matches the report content, which protects against corrupted reports.

- **Digest mismatch outcome** - the `report` command fails with a digest mismatch error when the report digest does not match its content. Do not paper over it. Tell the user the report's integrity cannot be confirmed and the report should be regenerated by re-running `verify`. Only bypass with `--skip-digest-check` if the user explicitly requests it. This flag is for testing purposes only.
